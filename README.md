# 走這條，一路順！（互動原型）

「這里需要你」長出的第一個解方：長輩用 App 導航，**白天找陰涼、晚上找安全**。設計重點是數位安全：不當低頭族、不用手機也能用。市政 debug松 概念原型，示範區為臺北市大安區。

- 線上版：`https://silver-safe-walk.hondao2026.workers.dev`
- 母體「這里需要你」：[hd2026-bit/zheli-needs-you](https://github.com/hd2026-bit/zheli-needs-you)；網站版也放在這裡的 `public/zheli/index.html`，網址加 `/zheli/`
- 網頁：`public/index.html`（單一檔案，不需建置）
- 伺服器：`src/worker.js`（道路施工資料轉送、安全標頭）
- 分析程式：`analysis/`，用開放資料重現所有數字（見 `analysis/README.md`）
- 版本：每一版都是一筆 commit；內容見 `CHANGELOG.md`

## 要解決的問題

臺北市的數據（`analysis/` 可重現）：

| 看見 | 數字 |
|---|---|
| 長者被撞的比例遠高於人口比例 | 2023–2025 行人事故 5,414 件，長者占 **35.6%**；行人死亡 58 件，長者 **44 件** |
| 長者白天也在外面走 | 白天 9–15 點的事故占比：長者 36.2%、其他年齡 31.5% |
| 最大肇因是車不讓人 | 長者事故最大肇因：車輛未依規定暫停讓行人先行（38.6%） |
| 危險路口集中 | 2023–2025 三年 76 m 內長者行人事故 ≥ 5 件的危險路口 **12 處**、3–4 件觀察名單 103 處 |
| 長者多的地方樹蔭不夠 | 超高齡（65 歲以上 ≥ 20%）且人行道樹冠覆蓋 < 40% 的里 **239 個**；其中優先里 57 個 |

一般導航只找最短路，不會避開日曬、暗路與危險路口；長輩也常因看不清螢幕、怕操作而不用。

## 怎麼解決

| 功能 | 說明 |
|---|---|
| 日夜自動切換 | 白天避曬（找樹蔭、騎樓、涼適點）；清晨與晚上改為安全優先（找亮的路、避開危險路口） |
| 危險路口提醒 | 走到危險路口前用語音提醒，並說明「為什麼」 |
| 道路施工 | 接臺北市今日施工資訊，路線 15 m 內有施工時提醒並加權 |
| 我要去那裡 | 首頁一個主按鈕：選目的地，比較最短與長者友善路線（白天陰涼、晚上路燈多、避開危險路口與施工）。未來串接氣候資料後，可加入保暖、避雨等路線 |
| 我要休息一下 | 走路途中按一下，選「上廁所／喝水／坐一下」，把最近的地點加進路線（A → 停靠點 → B）；到了會停下來等，休息好再帶回原路 |
| 廁所、喝水、舒適地點 | 首頁下方三個快捷鍵：公廁、飲水機、官方涼適點與關懷據點（原「納涼地點」） |
| 圖示優先、唸給我聽 | 每頁都有語音；大字級；少文字 |
| 打給家人 | 清晨、晚上首頁直接一鍵打給家人 |
| 地標指路 | 轉彎處 40 m 內有捷運出口時用出口指路 |
| 不用手機也能用 | 搭配紙本安心地圖（落地計畫中推動） |
| 佐證、方法分頁 | 全市高溫熱點里、危險路口、所有門檻的依據與敏感度測試 |
| 正式入口 | 網址加 `?app` 或加入主畫面：沒有 Demo 控制，依手機時間切換日夜，可離線 |

## SWOT 分析

### S 優勢（Strengths）
- **從數據長出來**：問題、門檻、示範區都有開放資料佐證，且每個門檻都有出處（聯合國、FHWA、PNAS 等），可用 `analysis/` 重現。
- **為長輩設計**：圖示優先、語音、大字級、打給家人、不用手機也能用，不是把一般導航放大字體而已。
- **日夜兩種需求一次解決**：白天的熱與晚上的暗，是同一群長輩、同一條路的兩個問題。
- **已接真實即時資料**：道路施工每次開啟都抓最新。
- **零成本、可離線**：單一 HTML、Cloudflare 免費方案；可加入主畫面、離線使用。
- **不蒐集個資**：設定只存在手機，沒有帳號、不回傳位置。

### W 劣勢（Weaknesses）
- **路線是模擬的**：目前只有大安區一條示範路線，還不是真的導航。
- **天氣是模擬的**：高溫燈號尚未接即時資料。
- **路燈資料舊**：2017 年，可能與現況不同。
- **樹蔭是推估**：靠樹木點位與樹冠寬假設，不是實測陰影；沒有考慮建築物陰影。
- **沒有長輩實測**：語音、字級、操作流程還沒有長輩實際走過。
- **只有臺北市**：資料格式依臺北市寫成。

### O 機會（Opportunities）
- **極端高溫越來越多**：熱傷害預防是衛生、環境單位的重點。
- **交通部推動高齡友善路口**：危險路口清單可直接給交通局作為改善優先順序。
- **官方涼適點已存在**：臺北市與環境部已建置涼適點，本工具讓長輩「找得到、走得到」。
- **關懷據點與社區活動**：據點是推廣紙本地圖與帶長輩走測的現成管道。
- **可回饋到城市規劃**：使用者實際走的路與避開的路，可作為補植行道樹、改善照明的依據。
- **可擴大**：方法公開，換城市資料即可複製。

### T 威脅（Threats）
- **導航責任**：若長輩照著走仍發生事故，可能有責任爭議；需清楚標示「輔助參考」。
- **長輩不用手機**：數位落差可能讓最需要的人用不到。
- **資料過期**：路燈、樹木、施工若不更新，推薦可能錯誤。
- **既有地圖 App 競爭**：大型地圖服務若加入遮蔭功能，本工具需定位在「長輩與社區」。
- **黑客松後沒人維運**：沒有主責單位就會停在原型。

### SWOT 對策

| 策略 | 做法 |
|---|---|
| SO（用優勢抓機會） | 把 12 處危險路口與佐證數據交給交通局，作為高齡友善路口的優先清單 |
| WO（用機會補劣勢） | 與關懷據點合作，帶長輩實地走測，補上使用者驗證 |
| ST（用優勢擋威脅） | 推廣紙本安心地圖，讓不用手機的長輩也受惠；頁面標示「輔助參考，請注意實際路況」 |
| WT（降低最壞情況） | 先接天氣與路網這兩個最大的缺口；第 100 日前確定維運單位 |

### 影響力 × 關注度

| | 關注度低 | 關注度高 |
|---|---|---|
| **影響力高** | 氣象署、資訊局、建管處 → **保持滿意**：資料需求講清楚 | 交通局、工務局、社會局 → **重點經營**：他們決定路口與照明能否改善 |
| **影響力低** | 大學、友善店家 → **定期告知** | 長輩、家屬、據點、里長 → **密切溝通**：使用者回饋決定成敗 |

## 100 日落地計畫

### 第 1–30 天：資料盤點

- 環保局：公廁補開放時間、飲水機補故障通報
- 公園處：公園座椅與遮陽棚建立點位
- 社會局：關懷據點、長青學苑位置資料確認無誤
- 環境部：確認 CoolMap 臺北點位介接方式
- 中央氣象署：連結天候資料
- 公園路燈工程管理處：路燈座標；警察局：交通事故資料（每半月更新）
- 工務局：介接今日施工資訊（每 10 分鐘），確認「影響通行」是否含人行道
- 衛生福利部：串連 AED 地圖

### 第 31–70 天：建置與共同設計

- 資訊局：以既有市府 App 或 LINE 官方帳號推播，以響應式畫面呈現，不另做新 App
- 樹木資料加建物陰影，推估各時段遮蔭
- 邀請長輩實地走測
- 事故熱點門檻（同地點長者 ≥ 2 件）與路燈加權，與交通局共同校正

### 第 71–100 天：試辦與評估、修正

- 辦理操作學習課程，限額招募高齡體驗人員進行測試。每個圖示看得懂嗎？語音聽得清楚嗎？
- 民眾通報（人行道破損、障礙物）轉新工處處理
- 指標：使用人數、高溫日外出次數、通報處理天數
- 長者重複事故路口回饋交通局，檢討行人綠燈秒數

## 平板 Demo
- iPad：設定 → 輔助使用 → 朗讀內容 → 聲音 → 中文（台灣），下載加強版語音
- Android：Google 文字轉語音下載「中文（台灣）」
- 瀏覽器開啟後「加入主畫面」可全螢幕；開場前先按一次 🔊 暖機
- 接藍牙喇叭或會場音響；關閉自動鎖定、開勿擾

## 兩種入口
- **Demo**：網址直接開，有「⚙ 控制」可切換時段、燈號（黑客松展示用）
- **正式入口**：網址後面加 `?app`，或「加入主畫面」後從圖示開啟。沒有控制面板，日夜依手機時間自動切換；字級與提醒設定記在這支手機上
