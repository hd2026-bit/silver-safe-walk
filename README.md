# 走這條，一路順！（互動原型）

「這里需要你」長出的第一個解方：長輩用 Web App 導航（不另做手機 App），**依天氣與時段，找最適合長輩走的路**：熱天找遮蔭、天暗走亮的路，並避開危險路口與施工；之後串接氣候資料，冷天、雨天也能提醒保暖、避雨。設計重點是數位安全：不當低頭族，靠語音提醒，不用一直看手機。市政 debug松 概念原型，示範區為臺北市大安區。

- 線上版：`https://silver-safe-walk.hondao2026.workers.dev`
- 母體「這里需要你」：[hd2026-bit/zheli-needs-you](https://github.com/hd2026-bit/zheli-needs-you)；網站版也放在這裡的 `public/zheli/index.html`，網址加 `/zheli/`
- 網頁：`public/index.html`（單一檔案，不需建置）
- 伺服器：`src/worker.js`（道路施工資料轉送、安全標頭）
- 分析程式：`analysis/`，用開放資料重現所有數字（見 `analysis/README.md`）
- 版本：每一版都是一筆 commit；內容見 `CHANGELOG.md`

## 要解決的問題

臺北市的數據（`analysis/` 可重現）：

| 看見 | 數字 |
|---|---|
| 長者被撞的比例遠高於人口比例 | 2023–2025 行人事故 5,414 件，長者占 **35.6%**；行人死亡 58 件，長者 **44 件** |
| 長者白天也在外面走 | 白天 9–15 點的事故占比：長者 36.2%、其他年齡 31.5% |
| 最大肇因是車不讓人 | 長者事故最大肇因：車輛未依規定暫停讓行人先行（38.6%） |
| 危險路口集中 | 2023–2025 三年 76 m 內長者行人事故 ≥ 5 件的危險路口 **12 處**、3–4 件觀察名單 103 處 |
| 長者多的地方樹蔭不夠 | 超高齡（65 歲以上 ≥ 20%）且人行道樹冠覆蓋 < 40% 的里 **239 個**；其中優先里 57 個 |

一般導航只找最短路，不會避開日曬、暗路與危險路口；長輩也常因看不清螢幕、怕操作而不用。

## 怎麼解決

| 功能 | 說明 |
|---|---|
| 日夜自動切換 | 白天避曬（找樹蔭、騎樓、涼適點）；清晨與晚上改為安全優先（找亮的路、避開危險路口） |
| 危險路口提醒 | 走到危險路口前用語音提醒，並說明「為什麼」 |
| 道路施工 | 接臺北市今日施工資訊，路線 15 m 內有施工時提醒並加權 |
| 我要去那裡 | 首頁一個主按鈕：選目的地，比較最短與長者友善路線（白天有遮蔭、晚上路燈多、避開危險路口與施工）。未來串接氣候資料後，可加入保暖、避雨等路線 |
| 我要休息一下 | 走路途中按一下，選「上廁所／喝水／坐一下」，把最近的地點加進路線（A → 停靠點 → B）；到了會停下來等，休息好再帶回原路 |
| 廁所、喝水、舒適地點 | 首頁下方三個快捷鍵：公廁、飲水機、友善店家（借廁所、裝水）、官方涼適點與關懷據點（原「納涼地點」） |
| 圖示優先、唸給我聽 | 每頁都有語音；大字級；少文字 |
| 打給家人 | 清晨、晚上首頁直接一鍵打給家人 |
| 地標指路 | 轉彎處 40 m 內有捷運出口時用出口指路 |
| 不用手機也能用 | 紙本安心地圖（後續推動，未列入 100 日計畫） |
| 佐證、方法分頁 | 全市高溫熱點里、危險路口、所有門檻的依據與敏感度測試 |
| 正式入口 | 網址加 `?app` 或加入主畫面：沒有 Demo 控制，依手機時間切換日夜，可離線 |

## SWOT 分析

### S 優勢（Strengths）
- **從數據長出來**：問題、門檻、示範區都有開放資料佐證，且每個門檻都有出處（聯合國、FHWA、PNAS 等），可用 `analysis/` 重現。
- **為長輩設計**：圖示優先、語音、大字級、打給家人、途中可加入休息點，不是把一般導航放大字體而已。
- **日夜兩種需求一次解決**：白天的熱與晚上的暗，是同一群長輩、同一條路的兩個問題。
- **已接真實即時資料**：道路施工每次開啟都抓最新。
- **零成本、可離線**：單一 HTML、Cloudflare 免費方案；可加入主畫面、離線使用。
- **目前不蒐集個資**：設定只存在手機，沒有帳號、不回傳位置（正式版接手機定位時需另做個資評估，見[上線評估](#上線評估)）。

### W 劣勢（Weaknesses）
- **路線是模擬的**：目前只有大安區幾條示範路線，還不是用路網計算的導航。
- **天氣是模擬的**：高溫燈號尚未接即時資料。
- **路燈資料舊**：2017 年，可能與現況不同。
- **樹蔭是推估**：靠樹木點位與樹冠寬假設，不是實測陰影；沒有考慮建築物陰影。
- **沒有長輩實測**：語音、字級、操作流程還沒有長輩實際走過。
- **只有臺北市**：資料格式依臺北市寫成。

### O 機會（Opportunities）
- **極端高溫越來越多**：熱傷害預防是衛生、環境單位的重點。
- **交通部推動高齡友善路口**：危險路口清單可直接給交通局作為改善優先順序。
- **官方涼適點已存在**：臺北市與環境部已建置涼適點，本工具讓長輩「找得到、走得到」。
- **關懷據點與社區活動**：據點是推廣與帶長輩走測、開操作學習課程的現成管道。
- **可回饋到城市規劃**：使用者實際走的路與避開的路，可作為補植行道樹、改善照明的依據。
- **可擴大**：方法公開，換城市資料即可複製。

### T 威脅（Threats）
- **導航責任**：若長輩照著走仍發生事故，可能有責任爭議；需清楚標示「輔助參考」。
- **長輩不用手機**：數位落差可能讓最需要的人用不到。
- **資料過期**：路燈、樹木、施工若不更新，推薦可能錯誤。
- **既有地圖 App 競爭**：大型地圖服務若加入遮蔭功能，本工具需定位在「長輩與社區」。
- **黑客松後沒人維運**：沒有主責單位就會停在原型。

### SWOT 對策

| 策略 | 做法 |
|---|---|
| SO（用優勢抓機會） | 把 12 處危險路口與佐證數據交給交通局，作為高齡友善路口的優先清單 |
| WO（用機會補劣勢） | 與關懷據點合作，帶長輩實地走測，補上使用者驗證 |
| ST（用優勢擋威脅） | 頁面標示「輔助參考，請注意實際路況」；據點開操作學習課程降低數位落差；不用手機的長輩後續以紙本安心地圖補足 |
| WT（降低最壞情況） | 先接天氣與路網這兩個最大的缺口；儘早確定主責與維運單位（見[上線評估](#上線評估)） |

## 100 日落地計畫

### 第 1–30 天：資料盤點

- 環保局：公廁補開放時間、飲水機補故障通報
- 公園處：公園座椅與遮陽棚建立點位
- 社會局：關懷據點、長青學苑位置資料確認無誤
- 環境部：確認 CoolMap 臺北點位介接方式
- 中央氣象署：連結天候資料
- 公園路燈工程管理處：路燈座標；警察局：交通事故資料（每半月更新）
- 工務局：介接今日施工資訊（每 10 分鐘），確認「影響通行」是否含人行道
- 衛生福利部：串連 AED 地圖

### 第 31–70 天：建置與共同設計

- 資訊局：以既有市府 App 或 LINE 官方帳號推播，以響應式畫面呈現，不另做新 App
- 樹木資料加建物陰影，推估各時段遮蔭
- 邀請長輩實地走測
- 事故熱點門檻（同地點長者 ≥ 2 件）與路燈加權，與交通局共同校正

### 第 71–100 天：試辦與評估、修正

- 辦理操作學習課程，限額招募高齡體驗人員進行測試。每個圖示看得懂嗎？語音聽得清楚嗎？
- 民眾通報（人行道破損、障礙物）轉新工處處理
- 指標：使用人數、高溫日外出次數、通報處理天數
- 長者重複事故路口回饋交通局，檢討行人綠燈秒數

## 上線評估

> 2026-10-24 評估。本專案是 **Web App（PWA）**，不另做手機 App：由市府 App 或 LINE 官方帳號推播連結，點開即用，可加入主畫面。

**結論**：試辦（1–2 個區、20–30 位長輩）約 **3–5 個月**，可能性中高；全市正式上線約 **6–9 個月**，可能性中，關鍵在主責單位與算路。

與 [100 日落地計畫](#100-日落地計畫) 的關係：100 日內完成資料盤點、共同設計與小規模試辦；路網計算與擴大試辦可能延續到第 5 個月，全市上線在 100 日之後。

### 現在做到哪裡

| 已經可以用 | 還是示範 |
|---|---|
| 介面、語音、日夜模式、「我要休息一下」流程 | 路線：只有大安區幾條手畫路線，尚未用路網計算 |
| 公廁、飲水機、涼適點、友善店家、路燈、騎樓、事故熱點等開放資料 | 定位：尚未接手機定位，「走路中」為模擬前進 |
| 道路施工每次開啟抓最新資料 | 天氣：高溫燈號為模擬 |
| 已部署、可加入主畫面、可離線 | 多數資料為一次性快照，尚未自動更新 |

### Web App 的優勢

- **不用上架審查**：沒有 App Store、Google Play 時程，推到 `main` 即上線
- **推廣門檻低**：點 LINE 連結就能用，不用下載安裝
- **整合成本低**：市府 App 或 LINE 官方帳號只要放連結、發推播，不需改它們的程式
- **維運成本低**：單一網頁加一個小伺服器（Cloudflare Workers）

### Web App 的限制（影響導航）

| 限制 | 影響 | 因應 |
|---|---|---|
| 螢幕關閉或切到其他 App 時，網頁通常停止定位 | 手機放口袋時，路口提醒不一定會響（iPhone 較明顯） | 導航時保持螢幕亮著；出發前先講清楚路上的重點（例：中間有一個要小心的路口） |
| 背景時語音可能不出聲 | 同上 | 同上；搭配震動 |
| iPhone 網頁推播需先「加入主畫面」 | 高溫提醒不一定送得到 | 推播改由 LINE 官方帳號發送，網頁負責顯示內容 |
| 定位需使用者按「允許」 | 第一次使用可能卡住 | 據點志工或家屬協助設定；不允許定位時可改選出發地點 |

### 三個階段

| 階段 | 內容 | 時間 | 可能性 |
|---|---|---|---|
| 1. 擴大展示版 | 大安區全區可查，天氣接即時資料 | 1–2 個月 | 高 |
| 2. 試辦版 | 1–2 個區用路網計算路線（依遮蔭、路燈、危險路口加權）、接手機定位；20–30 位長輩走測，並實測上述 Web App 限制 | 再 2–3 個月 | 中高 |
| 3. 正式上線 | 全市路網；LINE 官方帳號或市府 App 放連結、發推播；有人維運 | 再 2–4 個月 | 中 |

### 最大的關卡

1. **主責單位**：跨社會局、工務局、交通局、環保局的資料，需要一個局處掛名、編預算、負責維運
2. **算路**：把人行道資料變成可導航的路網，並依時段計算遮蔭、路燈與危險路口權重，是剩下最大的工程
3. **導航責任**：標示「輔助參考，請注意實際路況」，不宣稱最安全
4. **資安與個資**：手機定位屬個人資料；上線前需弱點掃描與個資衝擊評估
5. **長輩是否真的會用**：圖示、語音、字級需實地走測驗證
6. **資料更新**：店家、施工、天氣持續變動，需要自動更新與維護人力

### 提高成功率的做法

- 搭配既有平臺推播連結，不另做 App
- 先找願意試辦的單位（有長輩據點的社福單位，或區公所加上有意願的里長），累積真實使用紀錄
- 先縮小範圍：一個區、一種情境（去市場、去據點），把算路與走測做扎實
- 定位為「找休息點、避開危險」的輔助工具，不取代一般導航
